Que debemos hacer:
1. Un sistema que tenga:
o Un Gateway (puerta principal)
o Un Auth (login con usuario y contraseña)
o Un Catalog (servicio simple)
o Un Order (servicio simple)
2. Que el login genere un token (JWT).
3. Que si no hay token → dé 401 (no autorizado).
4. Que si hay token válido → deje pasar.

Crear el microservicio Catalog (8082) con endpoint de prueba y health.
TAREAS (JAVA):
1) Crear proyecto Spring Boot: services/catalog-service
2) Configurar server.port=8082 en application.yml
3) Crear controller: PingController con GET /ping que responda "catalog ok"

C1RM-4 — Auth Base
OBJETIVO:
Crear la base del Auth Service (8081) con JPA para usuarios (tabla creada por código).
TAREAS (JAVA):
1) Crear proyecto: services/auth-service
2) Configurar conexión PostgreSQL a authdb (application.yml)
3) Crear:
- Role enum (ADMIN, CUSTOMER)
- UserEntity (email, password, role)

4) Configurar JPA: ddl-auto=update para crear tablas automáticamente.

3) Implementar AuthService.register():

4) Endpoint: POST /auth/register en AuthController

C1RM-6 — Auth Login + JWT
OBJETIVO:
Implementar login que devuelva JWT con expiración y rol en el token.
TAREAS (JAVA):
1) Crear DTO LoginRequest (email, password)
2) Crear DTO TokenResponse (token, type)
3) Crear JwtService para generar JWT:
- subject=email
- claim role
- exp=15 min
4) Implementar AuthService.login():
- si credenciales inválidas -> 401
- si ok -> devolver TokenResponse
5) Endpoint: POST /auth/login
C1RM-7 — Gateway Security (401/403)
OBJETIVO:
Proteger /orders/** en el Gateway con validación JWT y roles.
TAREAS (JAVA):
1) En api-gateway crear:
- RouteValidator (define qué rutas se protegen: /orders/**)
- JwtAuthFilter (valida Authorization: Bearer)
2) Comportamiento:
- Sin token -> 401
- Token inválido/expirado -> 401
- Token válido pero role != ADMIN -> 403 (Forbidden)
- Token válido con role ADMIN -> permitir paso
3) Asegurar que gateway use la misma secret del auth-service.
